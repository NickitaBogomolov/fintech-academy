# Путь к пилоту, внедрение и масштабирование

## Почему ВТБ

- ВТБ стал оператором информационной системы для выпуска ЦФА в 2026 году и сам выстраивает процессы выпуска.
- Банк выпустил более 160 млрд ₽ ЦФА за 2024–2025 годы и планирует «коробочные» решения для корпоративных клиентов и встраивание ЦФА в розничные каналы.
- Решение закрывает обе задачи: пакет выпуска для корпоративного клиента и карточку инвестора для розничного канала.

## Сценарий пилота

| Этап | Срок | Что делаем | Результат |
|---|---|---|---|
| Подготовка | 2–3 недели | Подключаем шаблон решения о выпуске ВТБ, адаптер под платформу ОИС, разворачиваем в тестовом контуре | Пакет по форме банка |
| Параллельный прогон | 4–6 недель | Команда ЦФА готовит выпуски как обычно и параллельно в системе | Замер времени, итераций и расхождений |
| Рабочий режим | 4 недели | Новые эмитенты проходят через систему, юрист проверяет пакет | Метрики пилота, решение о внедрении |

## Что нужно от банка

- Шаблон решения о выпуске и описание шаблонов смарт-контрактов платформы.
- Тестовый контур с моделью: GigaChat или открытая модель через vLLM.
- 2–3 сотрудника команды ЦФА и юрист на время пилота.

## Внедрение в контур

- Разворачивание: docker compose на пилоте, Kubernetes в промышленной эксплуатации.
- Без внешних вызовов: модель, компилятор, EVM и анализатор работают внутри контура.
- Хранилище: PostgreSQL или Postgres Pro вместо SQLite из демо.
- Аутентификация через корпоративный каталог, журнал действий для внутреннего контроля.
- Развёртывание и подпись контракта остаются за платформой оператора: система не хранит ключи.

## Требования регулирования

| Норма | Как учтено |
|---|---|
| 259-ФЗ | Документ по шаблону оператора, обязательства зафиксированы в коде константами |
| 115-ФЗ | Контракт принимает заявки только от идентифицированных лиц |
| 152-ФЗ | В модель передаются только условия выпуска, без персональных данных инвесторов |
| Требования ИБ | Изолированное исполнение кода, без ключей подписи, без внешних сетей |
| Российское ПО | Открытый код, российские модели, PostgreSQL / Postgres Pro |

## Масштабирование

1. **Новые инструменты.** Структурные ЦФА с выплатой от индекса или металла, ЦФА с плавающей ставкой. Добавляются шаблоном документа и шаблоном контракта.
2. **Другие платформы.** Компилятор и среда исполнения вынесены в отдельный модуль: можно подключить другой язык смарт-контрактов, например chaincode для Hyperledger Fabric.
3. **Цифровой рубль.** Подготовка и предпроверка контрактов для платформы коммерческих смарт-контрактов Банка России.
4. **Нагрузка.** Сервис без состояния, проверки выносятся в очередь и отдельные воркеры.
