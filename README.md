# ЦФА Студия

Подготовка выпуска цифровых финансовых активов по описанию условий на естественном языке. Из одной спецификации система собирает решение о выпуске по шаблону оператора, смарт-контракт, график выплат и карточку инвестора, а затем проверяет, что код исполняет ровно то, что написано в документе.

## Зачем

Решение о выпуске и смарт-контракт должны совпадать до копейки, а после размещения их практически нельзя исправить. Сегодня их готовят вручную эмитент, юрист и оператор информационной системы. Продукт сокращает подготовку выпуска с дней до минут и убирает ручную сверку документа с кодом.

Подробно о проблеме, рынке и пилоте — в [docs](docs).

## Как это работает

```
Описание условий ─► разбор (правила или модель в контуре) ─► уточняющие вопросы
                                                              │
                                                              ▼
                                                      спецификация выпуска
                     ┌──────────────────┬───────────────────┼──────────────────┐
                     ▼                  ▼                   ▼                  ▼
             решение о выпуске    график выплат       смарт-контракт     карточка инвестора
            (шаблон оператора)  (календарь РФ)        (Solidity)
                     └──────────────────┴─────────┬─────────┘
                                                  ▼
             проверки: арифметика · календарь · регуляторика · исполнение в EVM · Slither
```

- **ИИ только на входе.** Модель или правила переводят текст в параметры и находят пробелы. Значение от модели принимается, только если цитата из текста подтверждает его.
- **Документ по шаблону.** Юридический текст фиксирован, подставляются только параметры. Оператор загружает свой шаблон без доработки кода.
- **Проверка исполнением.** Контракт компилируется и прогоняется в локальной EVM: сбор заявок, допуск инвесторов, выплаты по графику, погашение, возврат средств. Каждая выплата сравнивается с решением о выпуске.

## Возможности

- Разбор описания выпуска с подсветкой источников и вопросами о недостающих условиях
- Решение о выпуске в DOCX и Markdown по встроенному или загруженному шаблону
- График выплат с учётом выходных и праздников, правил переноса и округления
- Смарт-контракт на Solidity с 24 проверками до размещения
- Демонстрация типовых ошибок в коде и того, как их ловят проверки
- Карточка инвестора для розничного канала
- Продуктовые метрики и бенчмарк качества разбора
- Работа без внешних вызовов: модели GigaChat, YandexGPT или открытые модели в контуре

## Запуск

### Docker

```bash
cp .env.example .env
docker compose up --build
```

Интерфейс: http://localhost:8080

### Локальная разработка

Требуются Python 3.12, Node.js 20 и [uv](https://docs.astral.sh/uv/).

```bash
make install
make backend   # API на http://localhost:8000
make web       # интерфейс на http://localhost:5173
make test
```

### Языковая модель

По умолчанию описание разбирается правилами на сервере, без модели и сетевых вызовов. Чтобы подключить модель в контуре, укажите OpenAI-совместимый адрес в `.env`:

```bash
DFA_LLM_PROVIDER=openai
DFA_LLM_BASE_URL=http://vllm:8000/v1
DFA_LLM_MODEL=Qwen/Qwen2.5-7B-Instruct
```

Подходят vLLM, Ollama, YandexGPT и GigaChat через прокси gpt2giga. Если модель недоступна, сервис продолжит работать на правилах.

## Структура

```
backend/
  dfa_studio/
    domain/        спецификация, календарь, график выплат, проверки документа
    extraction/    разбор описания: правила, модель, уточняющие вопросы
    documents/     шаблоны решения о выпуске, форматирование, DOCX
    contracts/     генерация смарт-контракта
    verification/  компиляция solc, сценарии в EVM, Slither
    service.py     сборка пакета выпуска, метрики
    api.py         HTTP API
  toolchain/solc/  компилятор Solidity для работы без сети
  tests/
web/               интерфейс на React и TypeScript
docs/              проблема, рынок, метрики, пилот, сценарий демо
```
